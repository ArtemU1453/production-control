# 18. Развёртывание (GitHub Pages)

Приложение — статический веб-PWA, поэтому публикуется на **GitHub Pages** через
**GitHub Actions** без сторонних сервисов. Каждый push в `main` автоматически
пересобирает и публикует сайт.

## Постоянная ссылка

```
https://artemu1453.github.io/Kalkuliator-nariezchika-iOS/
```

(поддомен GitHub Pages в нижнем регистре; путь проекта сохраняет регистр имени
репозитория).

## Как это устроено

- Workflow `.github/workflows/deploy-pages.yml`: `npm ci` → `npm run check` →
  `vite build` → SPA-fallback → публикация каталога `dist/public`.
- Проект-сайт отдаётся из под-пути `/<repo>/`, поэтому клиент собирается с
  `VITE_BASE=/Kalkuliator-nariezchika-iOS/`. Значение должно точно совпадать с
  именем репозитория (регистр важен).
- Vite (`base`) переписывает пути ассетов и задаёт `import.meta.env.BASE_URL`;
  `<Router base>` (wouter) берёт базу оттуда, поэтому клиентская маршрутизация
  работает из под-пути.
- Прямые ссылки (deep links): GitHub Pages отдаёт `404.html` для неизвестных
  путей; workflow копирует `index.html` → `404.html`, поэтому любой маршрут
  поднимает SPA, а wouter сопоставляет адрес.
- Манифест PWA использует относительные пути (`./`) — корректен и в корне, и в
  под-пути.

Все настройки dev-safe: при локальной разработке и корневом деплое `base` = `/`,
поведение не меняется.

## Однократная настройка владельцем репозитория

1. **Settings → Pages → Build and deployment → Source: `GitHub Actions`**.
2. Смёржить ветку с workflow в `main` (или дождаться авто-запуска после мёржа).
3. Вкладка **Actions** → job **Deploy to GitHub Pages** → по завершении в шаге
   `deploy` будет ссылка на опубликованный сайт.

## Обновления

Любой последующий push в `main` публикует новую версию автоматически — ручных
действий не требуется. Запустить деплой вручную можно во вкладке **Actions**
(кнопка **Run workflow**).

## Примечание о Service Worker

Собираемый Vite-бандл включает манифест PWA (приложение устанавливается), но не
регистрирует service worker (в сборку он не входит — это поведение существовало
до этапа развёртывания). Офлайн-кэширование можно включить отдельным шагом при
необходимости; на работу онлайн-версии это не влияет.
