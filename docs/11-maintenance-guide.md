# 16. Инструкция по сопровождению проекта

## Окружение

- Node.js (LTS), npm. Установка: `npm install`.
- Разработка: `npm run dev:client` (Vite, порт 5000).
- Проверка типов: `npm run check` (или `npx tsc`).
- Production-сборка: `npx vite build` → `dist/public/`.

## Обязательные проверки перед коммитом

1. `npx tsc` — **0 ошибок**.
2. `npx tsc --noUnusedLocals --noUnusedParameters` — чисто в клиентском коде
   (исключения: `components/ui/*`, `pages/not-found`, `server/`).
3. `npx vite build` — без предупреждений; все чанки **< 500 КБ**
   (recharts изолирован в ленивом чанке).
4. Отсутствие `TODO/FIXME/console.*/debugger/any/!` в клиентском коде.
5. `git diff origin/main -- client/src/core/calculator/calculatorLogic.ts`
   — **пусто** (движок расчёта неизменен).

## Золотые правила

- **Не менять** алгоритм расчёта (`core/calculator/calculatorLogic.ts`).
- Изменения бизнес-моделей — **аддитивные** (новые опциональные поля),
  ради обратной совместимости со старыми записями.
- Новую зависимость добавлять только через композиционный корень
  (`core/di/container.ts`); экраны не создают сервисы сами.
- Пользовательские строки — только через `resources/strings.ts` (единый
  каталог, аналог `Localizable.strings`).
- Иконки — через `resources/icons.ts` (семантические имена, не прямые
  импорты lucide).

## Как добавить (без нарушения архитектуры)

- **Новый экран**: View в `*/views`, ViewModel-хук `use*.ts`, маршрут в
  `App.tsx`, строки/иконки в ресурсах.
- **Новый вид отчёта**: построитель в реестр `reports/builders` — вызывающий
  код не меняется.
- **Новый формат экспорта / транспорт e-mail / провайдер хранения**: реализовать
  соответствующий интерфейс и зарегистрировать в реестре.
- **Новое поле модели**: добавить опционально; при несовместимости — поднять
  `DB_VERSION` и реализовать миграцию.

## Проверочные harness'ы

Автономные `.mts`-скрипты поднимают всю систему на in-memory `KeyValueStore`
через `createAppContainer` и запускаются `npx tsx`. Они проверяют полный
производственный цикл, edge-cases и нагрузку. Скрипт создаётся на время
проверки и удаляется после (в репозитории не хранится). Шаблон:

```ts
import { createAppContainer } from "@/core/di/container";
class MemoryStore { /* read/write/remove поверх Map */ }
const app = createAppContainer(new MemoryStore());
// ... вызовы сервисов, assert'ы
```

## Обслуживание данных в проде

Экран «Настройки → Обслуживание»: проверка целостности и связей (только
чтение), очистка кэша. «Диагностика»: версии, счётчики, размер БД.
«Журналы»: ошибки и аудит. «Резервное копирование»: копия/восстановление/
экспорт JSON.

## Диагностика проблем

- Приложение не открывается / белый экран → перехватит `ErrorBoundary`,
  запись появится в журнале ошибок; при повреждении данных `LocalStorageStore`
  вернёт `undefined` вместо падения.
- Расхождение данных → «Обслуживание → Проверка целостности».
- Переполнение хранилища → выгрузить резервную копию, при необходимости
  очистить журналы; долгосрочно — переход на IndexedDB (Roadmap).
