# 7. Бизнес-процессы

## Полный производственный цикл

```
Поступление сырья  → warehouse.receiveBatch → Jumbo(onStock) + «Приход»
Начало работы      → warehouse.startUsage   → Jumbo(inWork)  + «Начало использования»
Расчёт заказа      → calculation.calculate (движок) даёт план раскроя
Выполнение заказа  → warehouse.completeCalculation (транзакция):
                       • списание остатка Джамба
                       • создание CuttingSession (заказ+результат)
                       • рулоны: в заказ / на склад (RollDestination)
                       • обновление накопителей и операции «Расчёт»
Несколько заказов  → повторение расчёта по тому же Джамбу
Остаток < порога   → becameWriteOff → Jumbo(toWriteOff)
Закрытие Джамба    → warehouse.closeJumbo:
                       • фиксация технологического остатка (Waste)
                       • снимок ArchivedJumbo + замороженная статистика
                       • Jumbo(archived)
KPI                → AnalyticsService.overview (KpiEngine)
Отчёты             → reportCenter.service.generate → ReportData
PDF                → documents.service.preview / pdfBuilder
Email              → documents.service.generateAndSend (транспорт)
Аналитика/Архив    → данные попадают в аналитику и архив автоматически
```

Каждый ключевой шаг фиксируется в журнале аудита (`AuditAction`).

## Жизненный цикл Джамба

```
        receiveBatch                startUsage
  ┌───────────────────┐      ┌───────────────────┐
  │                   ▼      │                   ▼
(нет) ───────────► onStock ──┴──► inWork ──► toWriteOff ──► archived
                     ▲            │  ▲            │             ▲
                     │  расчёты   │  │ остаток<порог            │
                     └────────────┘  └───────────┘   closeJumbo │
                                                                 │
                              (снимок ArchivedJumbo) ────────────┘
```

- **onStock** — Джамб оприходован, ждёт использования.
- **inWork** — начато использование; по нему выполняются заказы.
- **toWriteOff** — остаток опустился ниже `jumboThresholdM` (по умолчанию
  300 м); для следующего заказа берётся новый Джамб.
- **archived** — Джамб закрыт; его данные заморожены снимком `ArchivedJumbo`
  и исключены из активного склада.

Инварианты: остаток никогда не отрицателен; накопительная статистика
обновляется инкрементально и не пересчитывается; история операций
неизменяема (откат помечает записи `isReverted`, но не удаляет их).

## Диаграмма потоков данных

```
 UI (Views) ──events──► ViewModels ──calls──► Services/Centers
      ▲                                            │
      │ state                                      │ repositories
      │                                            ▼
   Toaster/                                   KeyValueStore
   ErrorBoundary ◄───errors───  ErrorLog ◄──  (localStorage)
                                                   ▲
     Отчёты/аналитика ◄─ ReportRepository (агрегация 1×) ─┘
```

Складские операции меняют сигнатуру данных, что инвалидирует кэши отчётов и
аналитики; повторное открытие экранов без изменений данных не пересчитывает
агрегаты.

## Обработка ошибок пользователя

- Валидаторы (`services/validation`) не пускают некорректный ввод (пустые
  обязательные поля, некорректный код материала, неположительные размеры).
- Движок расчёта сам отклоняет недопустимые параметры (ширина материала
  550–910 мм, доп. размер 20–310 мм и не больше остатка и т. п.) с понятным
  сообщением, которое показывается пользователю.
- E-mail-адреса проверяются и разделяются на валидные/невалидные перед
  отправкой; импорт резервной копии отклоняет некорректный формат.
